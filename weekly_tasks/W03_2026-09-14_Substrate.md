## 2. Track S —— 本周主战场

> ⚠️ **两条 W02 新发现的硬约束,贯穿所有组件:**
> 🔴 **① "环境有没有变"不能当判据** —— 即使跑不存在的开关也重写 >1.6 MB,且**退出时**才写 8 个文件 ⇒ **一切状态判定必须基于语义,不能基于文件系统 diff**
> 🔴 **② 三个可观察通道无一说实话** —— 退出码正常 / 输出文件不存在 / 日志只写 `Start -`,真相在第四处(Model 目录 mtime)⇒ **verifier 必须自己造判据**

### S1 状态序列化器(生产版)· 1.0 人日

T-10 已经测过一版,五条判据里四条满分。**本周把它变成生产件。**

| 要求 | 依据 |
|---|---|
| 🔴 **必须记选中项** | **P32**:展开树节点会顺带选中它,收起不还原 ⇒ 对展开幂等、**对选中不幂等** |
| 🔴 **窗口几何不可归一化** | Batch Export *"export is processed according the displayed size"* ⇒ 几何是**语义相关**的 |
| **可折叠层级树** | M2 的前提:`observe(path=None)` 按需展开 |
| **稳定 / 敏感 / 精确 / 还原 四条判据回归** | 沿用 T-10 的测法,**加上第五条(全快照回基线)作为已知失败项**,不许静默通过 |
| ⚠️ **不得用文件系统 diff 判"变没变"** | 硬约束 ① |

**DoD**:`environments/common/serializer.py` + 五条判据的回归测试;第五条标为 `xfail` 并注明 P32。

### S2 typed action 层 + state diff · 1.0 人日

**11 个语义中立原语**(描述中不得出现 RRC / 切换 / 分箱 / Favorite / 采样):

```
screenshot  read_tree  read_window_list  click  drag  set_field
type  key  scroll  export  read_file
```

| 要求 | 依据 |
|---|---|
| 🔴 **每个动作返回 `state_diff`,不是 `ok`** | 硬约束 ②;M3 的全部基础 |
| 🔴 **`drag` 必须实现** | XCAP 的主要交互方式(参数树 → 工作区、Alt+拖放叠加) |
| ⭐ **`apply_filter` 作为结构化动作的范例** | filter = `(param, op ∈ {=,<>,>,>=,<,<=}, value, linker ∈ {AND,OR,None})` 有序列表 —— 声明式,可生成可 diff |
| 🔴 **`apply_filter` 的 state diff 必须扫全工作区** | Filtering 是**全局**的(跨 Graph/Map/Table/CDF/PDF) |

**S2.5 动作表 manifest(0.25d)**:版本化落盘 + **领域词黑名单**的语义中立性检查(CI)。

**DoD**:11 个动作跑通;`apply_filter` 的全局副作用能被 diff 捕获;manifest 落盘。

### S3 verifier 栈 · 0.75 人日

🔴 **本软件没有便宜的、可观察的成败判据** —— 这是 S3 的设计前提,不是障碍。

| 层 | 判据 |
|---|---|
| 导出文件比对 | 大小 + SHA-256(⚠️ **只对 `-MB` 形态成立**,`.fav` 那条不可外推) |
| 状态谓词 | 走 S1 |
| ⭐ **第四通道** | **Model 目录与内部每个文件的 mtime** —— T-09 证明这是唯一说实话的通道 |
| **阳性对照强制** | 每个 verifier 必须带一个"已知应当成功"的对照(C5.3;**W01 已因缺它产出三次假数字**) |

**DoD**:`bench/oracles/` 三层接口 + 每层一个阳性对照;`.fav` 通路的静默失败能被检出。

### S4 recorder + 检查点控制器 · 0.75 人日

```python
ckpt.workspace()   # 清 filter + All Window Close + 重载 .wrk + 🔴 显式复位选中项(P32)
ckpt.model()       # KX → INI → MOP "<model>"
ckpt.rebuild()     # -CM 从 log 重新建模
```

| 要求 | 依据 |
|---|---|
| 🔴 **`workspace()` 必须显式复位选中项** | P32 |
| 🔴 **代价是数据量的函数** | 小数据 9–22 s,真实体量分钟级 ⇒ 记录 `f(size)` 而非常数 |
| **recorder 全程录制** | 动作 + 观测 + state diff → replay 语料 |

**DoD**:三级各测 3 次取均值**并在两种数据量上各测一次**;recorder 产出可 replay 的轨迹。

### S5 RPC controller ↔ worker · 0.5 人日

controller(联网,跑 LLM)↔ worker(隔离侧,只驱动软件)。
⚠️ **VM 与 huang 不在同一网络,只有 VNC 云中继,大文件过不去** —— RPC 协议必须**只传状态与动作,不传大文件**。

**DoD**:hello-world 往返 + 一个 typed action 端到端。

### S6 replay 离线环境 · 0.5 人日

用 S4 的轨迹做**不占 license** 的回放环境 —— agent 迭代的主力场。

**DoD**:一条录制轨迹能完整回放,状态逐步一致。
