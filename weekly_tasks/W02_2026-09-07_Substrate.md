## 2. Track S — Substrate 骨架

### S1 ⭐ 状态序列化器 v0（本周核心）

产出一份**规范化、层级化、可 diff** 的文本 workspace 视图。

| 步骤 | 内容 |
|---|---|
| S1.1 | 定义 schema：`/workspace`(model, 解析剖面) `/views`(7 个分析 tab + Message/Signaling Flow/Synchro Viewer) `/selection` `/derived`(⭐ 见下) `/config` |
| S1.2 | 从 W01-A5 的 UIA dump 实现提取器 |
| S1.3 | **稳定性测试**：同一 UI 状态连续 dump 10 次，要求逐字节一致 |
| S1.4 | **diff 测试**：执行一个已知动作，检查 diff 是否恰好反映该动作的语义 |

**三条设计约束（W01 之后已修订）**：

1. **归一化分两类** —— *表现性*字段（滚动像素偏移、光标位置）归一化掉；**语义性字段必须保留**：
   - **窗口尺寸 / 图表可视范围**（手册：*"export is processed according the displayed size"*）
   - **`analysis_config` 全体**：采样率（11 档）、解析剖面、全局 filter、分箱公式（9 种）、`First/Last`、呼叫区间模式、`UTC`
2. ⭐ **必须覆盖派生状态**：Area/Route Binning 结果会作为新参数挂进参数树，Route Binning 还能再生成新 Model → `/derived` 子树，且 reset 必须清理
3. **分层可折叠**：482k 条消息不能全进 context；高基数视图只暴露摘要 + 查询接口

- **工时**：2 天 · **DoD**：`softwarex-agent/substrate/serializer.py` + 稳定性/diff 测试通过

### S2 Typed action layer v0

`click(node)` / `set_field(node,v)` / `open_panel(x)` / `apply_filter(expr)` / `seek(t)` / `export(view,path)`，兜底 `click_xy`。每个动作返回 **state diff**（M3 的前提）。

> ### ⭐ 动作层的暴露方式:MCP 是传输,不是架构
>
> ```
> Layer 0   注入原语(UIA / SendInput / 坐标)      ← A9 在这里测,不经任何中间层
> Layer 1   typed action + state diff             ← M2/M3,我们的贡献,自己实现
> Layer 2   暴露方式(MCP / 函数调用 / CLI)         ← 可替换
> ```
>
> **MCP 放在 Layer 2 是好的**:与 typed action 的 schema 天然吻合;正好落在 controller↔worker 的 RPC 边界上;
> Wireshark 与 XCAP 暴露同一套 schema 使"跨软件泛化"证据更硬;capacity=2 的实例池与 `λ·N_live` 预算**在这一层记账最自然**。
>
> 🔴 **但有一条红线:动作表就是我们声称不存在的那份软件手册。**
> 若预先提供 `open_rrc_signaling_view()` 这类带领域词汇的动作,就等于把 M1 与 M6 的答案直接塞进环境。
> ⇒ **初始动作面必须语义中立**,只有:
> `screenshot / read_tree / click / drag / set_field / type / key / read_window_list / export`
> —— 描述里**不得出现** RRC、切换、分箱、Favorite 这类词。软件的语义由 agent 自己建立,那正是 M1 的产出。
>
> 🆕 **S2.5 动作表 manifest(0.25d)**:每次 run 把动作表版本化落盘,含每个动作的名称、签名、描述全文。
> **"agent 在 t=0 知道什么"是审稿人必问的问题,答案必须是一个精确可引用的产物。**
> 语义中立性需人工过一遍。
>
> ⚠️ 两个坑:① **MCP 看不见静默失败** —— 它返回调用成功与否,不是 GUI 状态是否真的变了。
> **M3 的验证必须留在 Layer 1:每个动作返回 state diff,不是 `ok`**。
> ② **模态框会挂死调用**(A6 已证 CLI 会弹 `your path` 框)—— 包 CLI 的动作必须带模态窗口看门狗,超时要短。

> ⭐ **`apply_filter` 现在有确定的文法，不再是占位符**（[[XCAP-KB-FINDINGS]] §5.7.5）：
> ```python
> Clause = (param: str, op: Literal["=","<>",">",">=","<","<="], value: str|float, linker: Literal["AND","OR",None])
> apply_filter(name: str, clauses: list[Clause])   # 命名的、可存取的、全局生效的对象
> ```
> 两条设计后果：① 这是动作空间里**第一个真正结构化的动作**，应作为 typed action 的范例先做通；② filter **全局生效**（跨 Graph/Map/Table/CDF/PDF），所以 `apply_filter` 的 state diff **不能只看当前窗口** —— 必须扫全工作区，否则会漏报副作用。这条同时验证 `ckpt.workspace()` 里"清 filter"的必要性与充分性。

⚠️ **必须单列 `drag(from_node, to_target, modifiers)`** —— XCAP 主要交互方式是从参数树拖放到工作区（Alt+拖放叠加），DCI Analysis 建列表、Area Binning 建箱都要拖。按 W01-A5/A9 的实测结果决定实现方式。

- **工时**：1 天 · **DoD**：每个动作有 pre/post 状态记录

## 3. Track T — L1–L4 任务生成（不占 license）

> **为什么先做 L1–L4**：有精确 oracle、不受 T1/T2/T3 影响、可大规模自动生成、且 **N2 恰在 L2 咬得最狠**。即使 L5 全线失败，这部分仍构成论文。

### T1 ⭐ 任务生成器 v0

基于 W01-B3' 的 15 个样例，写生成器：

| 级 | 生成方式 | Oracle |
|---|---|---|
| L1 检索 | 从 diag parser 输出中随机取事件 → 措辞成"找到 X" | 状态谓词 |
| L2 计算 | **先写 GT 计算，再措辞成任务**（oracle-first） | 精确 + `analysis_config` |
| L3 配置 | 指定目标视图/过滤/图表配置 | 状态谓词 |
| L4 对比 | 多 trace / 多实体，用 UDR `Comparison` 类型（支持 2–50 model） | 导出文件比对 |

- **工时**：2 天 · **DoD**：每级 ≥20 个自动生成的实例

### T2 ⭐ 现成模板收割（KB 已提供）

把 XCAP 内建分析功能直接转成任务模板，**每个都自带 oracle**：

| 功能 | 内建 oracle | 目标级 |
|---|---|---|
| **Message Duration Time Analysis** | min/max/avg + 阈值违规 Call Number | L2 |
| **Area Binning Result** | Min/Max/Avg/Count/Threshold/超阈比例，可导 xls | L2/L4 |
| **Finding Missing Neighbors** | 三参数检测器（邻区阈值 + 与服务小区差值 + 持续时间） | L2/L3 |
| Coverage Info / Sector Swap / PCI Match Ratio / Shadow Area | 各自的结果表 | L2/L3 |

⚠️ Area Binning 与地图类**依赖 Map 引擎授权**（W01-C4 的结论）。若无授权，从模板库剔除。

- **工时**：1 天 · **DoD**：≥8 个模板，每个含参数化方案与 oracle 定义

### T3 🔴 GT 管线：复刻 XCAP 聚合语义

依据 W01-B1（diag parser 通路）+ W01-A4（采样标定）+ KB 的官方计算逻辑文档：

- 实现 1 秒分箱与 11 档采样率
- **counter / gauge / event 三类语义分开**（T7：`num_rlf_issued` 是累计量，KPI 是箱内差分）
- 实现已文档化的 KPI 口径（LTE PDSCH Throughput、5G-NR MAC PDSCH/PUSCH、RLC DL Dropped PDUs）
- 🔴 **逐参数标定"静默覆盖"** —— Area Binning 对 Sector/PSC 类参数无视所选公式强制用 Mode。**不能假设选了 Average 就是 Average**，每类参数都要实测
- **工时**：2 天 · **DoD**：`gt_pipeline/`，与 XCAP 导出在 ≥3 个 KPI 上数值一致

### T4 Detector battery 起步（为 L5 铺路）

按 W01-B3 的现象清单实现前 8 个 detector，输出 `{存在?, 时间窗, 强度, 置信度}`。
⚠️ 聚合语义必须与 T3 一致。可用 XCAP 内建功能（Missing Neighbors、PSC Pollution）交叉校验。

- **工时**：1.5 天 · **DoD**：8 个 detector 可跑
