## 0. 一句话判断

**契合度真实且不平凡,但必须重构问题陈述** —— 不能把"software-use agent"当卖点,
要把它当**手段**,卖点是**"被分析软件锁住的存量科学数据"**。

| 维度 | 判断 |
|---|---|
| 与 in-scope 的对齐 | ✅ **很强** —— 特征提取 / 元数据生成 / 数据管线,全中 |
| 与 out-of-scope 的关系 | ✅✅ **完美** —— *"Research to collect de novo datasets is out of scope"*,<br>而我们 W01/W02 刚**用实测证明了不需要新采集**(D1/D4 门通过) |

| 时间 | ⚠️ 41 天,且与 SIGCOMM(02-01)冲突 —— 见 §6 |

## 1. 🔴 必须重构:问题陈述

### 1.1 不能这么写

> ~~"我们做了一个能操作商业 GUI 软件的 agent,以 XCAP 为例。"~~

这在 SIGCOMM 是主贡献,在 NSF 26-512 里是**跑题** —— 评审看到的是一篇 agent 论文,
不是一个 dataset 提案。而且 XCAP 的用户社区(运营商 + 少数网络实验室)**撑不起"community breadth"这条评分**。

### 1.2 应该这么写

**核心论点(三句话)**:

> ① 大量存量科学数据的**科学含义不在文件里,在厂商分析软件里**。
> 原始文件是字节;RSRP、峰面积、细胞亚群计数这些**科学量,要经过厂商软件解码、聚合、计算之后才存在**。
>
> ② 因此让这类数据"AI-ready"**不是格式转换问题,是软件操作问题** ——
> 而这个操作目前**只能由人在 GUI 里手工完成,不可规模化、不可复现、不可审计**。
>
> ③ 🔴 更糟的是:**我们实测证明,这些软件对自己的行为撒谎。**
> ⇒ **即使是现在由人手工提取的数据,也带着静默的语义错误。**
> **AI-readiness 的第一步,是先搞清楚这个工具到底算了什么。**

### 1.3 给这个问题起个名字

候选:**Instrument-Locked Datasets** / **Tool-Mediated Datasets** / **Analysis-Locked Data**

我倾向 **"instrument-locked"** —— 它把矛头指向一个**可识别的、跨学科的数据类别**,
而不是指向某个软件或某个学科。

### 1.4 ⭐ 为什么这个 framing 有竞争力

**我的判断:这一轮大多数提案会写"元数据 schema + embedding + 知识图谱"。**
我们这条路子完全不同,而且:

- 它指出了一个**真实存在、被广泛承受、但没有被命名过**的瓶颈
- 它有**实测证据**,不是论证出来的(见 §2)
- 它天然 out-of-scope-proof:**我们不采数据,我们解锁已采的数据**

## 2. 我们已有的资产 → 映射到评分项

### 2.1 问题表征的实测证据(这是最硬的)

| 资产 | 数字 | 在提案里当什么 |
|---|---|---|
| **软件自述不可信表** | **13 行**,十余条独立调查线,**全部真机/全库实测** | ⭐ **提案的开篇证据**。不是文献综述 |
| **配置决定真值(T5)** | 同一份数据,"最差 SINR" = **All 档 −20.0 / 1Sec 档 −12.9** | **数据完整性论证的量化实例** |
| **沉默的破坏性默认值** | **5 个**,来自 4 份互相独立的官方文档 | 同上 |
| **"没有便宜的成败判据"** | 退出码正常 / 输出文件不存在 / 日志只写 `Start -`,**真相在第四处(mtime)** | 🔴 **A 级证据,有受控复现** |
| **版本号不唯一确定二进制** | 同一版本号,**两代 Wireshark 插件并存** | **可复现性论证** |
| **"层"不是软件的一等公民** | 308 张表按 RAT × 功能块组织,**`Layer2` 零表** | 元数据 harmonization 的真实难点 |

⭐ **这一组的力量在于:它证明"手工提取的科学数据本身就不可靠",而这是 NSF 明确要评的
"dataset security, integrity"。** 我没见过别的提案能拿出这种证据。

### 2.2 ⭐⭐ 最独特的可交付物:**语义溯源目录**

> **一份机器可读的记录:这个软件的每一个操作,在每一个配置下,实际计算的是什么;
> 以及它的文档在哪里说错了。**

这是一个 **dataset about datasets** —— 正好是 solicitation 说的 *metadata generation*。

它的价值:

| | |
|---|---|
| **对已有数据** | 任何用该工具提取过的数据集,都能回溯查出自己带了哪些语义偏差 |
| **对 AI 管线** | 提供了"这个数字是什么意思"的机器可读定义,而厂商文档做不到 |
| **对治理** | 直接回答 NSF 的 *"dataset integrity"* 评分项 |
| **可持续** | 随版本增长,社区可贡献 —— 正好对应 *"community contribution process"* |

### 2.3 验证架构(回答"agent 提取的数据凭什么可信")

我们已经建成的**离线 oracle 通路**就是答案,而且已有数字:

```
厂商软件  ──┐
            ├──→  双通路交叉验证  ──→  提取结果可审计
独立解析器 ──┘
```

| 已实测 | |
|---|---|
| 容器格式全解 | 283 MB/s,15.3 GB 零重同步,**跨四条产线成立** |
| L1 逐 code 对账 | **99.4%**(165/166) |
| L2 双通路交叉校验 | **50/50**,映射 21/21 |
| ⚠️ 方法论教训 | **交叉验证前必须先证明两条通路独立** —— BMF 表是导出的后台镜像,拿它当第二通路是自欺 |

⭐ **这套东西可以写成一个通用原则**:*任何 agent 提取的科学数据,
都必须有一条不经过该 agent、也不经过该厂商软件的独立验证通路。*

### 2.4 Agent 架构(在提案里是**手段**,不是卖点)

36 条能力 / 六机制 / RSI 三闭环 —— 在提案里压缩到 **§2 研究计划的一小节**,
重点讲**为什么通用 computer-use agent 不够**(零文档、零演示、不可逆、正确性不可见)。

## 4. 提案结构(按 solicitation 的五节)

> ⚠️ **页数限制未在 solicitation 中写明** —— 需查 PAPPG 确认(NSF 标准通常 Project Description 15 页)。**这条要第一周确认。**

### §1 Vision and community benefit

| 要素(solicitation 原文要求) | 我们写什么 |
|---|---|
| 能被解锁的根本科学问题 | 跨域举 3–4 个**具体**的:免疫学的门控可复现性危机 / 蛋白组学的厂商锁定 / 材料表征的峰拟合 / 无线网络的跨层归因 |
| 现有数据集描述 | **强调体量已经存在** —— 我们自己的 15.3 GB + 合作域各自的存量 |
| 社区范围与广度 | 🔴 **最弱一节,见 §5** |
| 与相关数据工作的关系 | 诚实处理 ProteoWizard / msconvert 这类**已部分解决格式转换**的工作,<br>说清**我们解决的是它们解决不了的那半**(语义与配置,不是容器) |

**Keywords 行(必须 2–5 个 NSF 学部,按优先级)**:
建议 `CISE, BIO, MPS, ENG`

### §2 Research plan

四个推力:

| # | 推力 | 我们的基础 |
|---|---|---|
| **R1** | **语义标定** —— 自动发现工具的操作在各配置下实际计算什么 | C1.3 + T5 实测 |
| **R2** | **可验证提取** —— agent 驱动工具完成提取,每步有独立通路核验 | 六机制 + 离线 oracle |
| **R3** | **跨域泛化** —— 同一套架构移植到 ≥3 个仪器域 | 🔴 **待建,这是新工作** |
| **R4** | **就绪度评估** —— 自动判定一个存量数据集"离 AI-ready 还差什么" | 🆕 直接对应 solicitation 的 *"automated platforms assessing dataset readiness at scale"* |

⭐ **R4 值得单独突出** —— solicitation 明确点了这条,而我们的 detector battery +
13 项测试 + 五个决策门,**本质上就是一套"数据集就绪度评估"方法论的原型**。
这是我们已有工作里**最没被利用、却最对口**的一块。

### §3 Dataset governance and integrity

⭐ **我们最强的一节。** 内容:

- **语义溯源目录**(§2.2)作为治理机制
- **双通路独立验证**作为完整性机制
- **社区贡献流程**:任何人可提交"我发现该工具在配置 X 下实际算的是 Y",走验证流程入目录
- ⚠️ **诚实写出访问管理的难点**:厂商软件有许可证限制(我们实测 capacity 受限),
  **这既是约束也是论证** —— 正因为 license 稀缺,才更需要 agent 而不是靠人力堆

### §4 Dataset availability and infrastructure

| 要素 | 我们的计划 |
|---|---|
| 用户参与 | 每域的伙伴实验室 + bi-annual 虚拟会议(solicitation 要求,**要列预算**) |
| 访问基础设施 | 提取产物 + 语义目录走公开仓库;**原始厂商文件不分发**(版权 + 体量) |
| 采纳度量 | 目录条目数 / 社区贡献数 / 复用该管线的下游工作 |
| 可持续 | 目录是**累积资产**,随厂商版本增长;agent 与 benchmark 开源 |

🔴 **必须正面处理**:我们自己的实验室数据是**专有积累**。
⇒ 交付物定位为 **① 提取 agent ② 语义目录 ③ 提取后的特征数据集 ④ 验证工具**,
**不是原始 trace**。这个要在 §4 写清楚,别让评审自己发现。

### §5 Flagship justification —— **不写**(投 Impact)

## 5. 🔴 最大的风险:社区广度

### 5.1 问题

评分项原文:*"Size, commitment, potential impact, breadth and outreach plan of the communities"*

**单靠 XCAP / 无线网络,这一条会被打低分。** 这是我对本提案最大的担心。

### 5.2 解法:招 2–3 个跨域伙伴

要找的是**同构的痛点**:数据已存在 · 科学含义只在厂商 GUI 里 · 提取靠手工 · 结果不可复现。

| 候选域 | 软件 | 为什么同构 | NSF 学部 |
|---|---|---|---|
| ⭐⭐ **流式细胞术** | FlowJo | **门控策略决定细胞亚群计数** —— 这就是 T5,而且免疫学界公认是**可复现性危机** | BIO |
| ⭐⭐ **质谱 / 蛋白组学** | Xcalibur / FreeStyle(.raw) | 厂商锁定最著名;⚠️ 但 ProteoWizard 已解决**格式**那半,要讲清我们解决的是**语义**那半 | BIO / MPS |
| ⭐ **材料表征** | CasaXPS / DIFFRAC(XPS、XRD) | **峰拟合参数决定结论**,手工在 GUI 里做 | MPS / ENG |
| ⭐ **冷冻电镜 / 电镜** | DigitalMicrograph / Velox | 专有格式 + 专有处理链 | BIO |
| 我们自己 | XCAP | 已有全部实测 | CISE |

⭐ **流式细胞术是我的首选第二域** —— 门控与 T5 的同构太干净了:
*同一份 FCS 文件,不同门控策略给出完全不同的细胞亚群计数,而门控是手工在 GUI 里画的。*
这个例子评审一看就懂,而且它有一个现成的、被广泛承认的可复现性危机作为背书。

### 5.3 🔴 决策门(10-14)

| 条件 | 动作 |
|---|---|
| **≥2 个域有 PI 明确口头承诺 + 愿出 Letter of Collaboration** | ✅ **投 Impact** |
| 只有 1 个,或都只是"有兴趣" | 🟡 **降级投 Planning**,把联盟建设写成 Planning 的主要产出 |
| 一个都没有 | 🔴 **不投**,今年跳过,明年 11 月再来(每年一轮,不是一次性机会) |

⚠️ **最后一行是认真的。** 社区广度是明写的评分项,没有伙伴的单域提案在这个 solicitation 下
大概率是陪跑 —— 而写提案要吃掉 2–3 人周,**正好撞在 substrate 和 agent 的建设期上**。
