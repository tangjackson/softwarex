## F0 野心锚点 —— 十年后我们希望被怎么引用?

| 候选 | 一句话 | 野心 | 风险 |
|---|---|---|---|
| A 工具 | "一个能从厂商软件里提取数据的 agent" | 低 | 就是 v1 否掉的那个 |
| B 数据集 | "N 个领域的 instrument-locked 数据被解锁成 AI-ready 数据集" | 中 | 像 Impact,拼盘感 |
| **C 基础设施 + 新学科问题** ⭐ | "**让每一台科学仪器的分析软件都可被机器审计** —— 建立 *instrument semantics* 作为 AI-ready 数据的缺失一层" | 高 | 需要论证它是研究而不是工程 |
| D 全国性服务 | "全国核心设施(core facilities)的存量数据统一解锁服务" | 最高 | 运营承诺重,3 年做不完 |

**推荐 C,D 作为 vision 的远景段落。**
C 的关键是把贡献从"解锁某批数据"抬到"**定义并建立一个此前不存在的数据层**":
原始字节 → **[instrument semantics:这个工具在这个配置下到底算了什么]** → 科学量 → AI。

**过关标准**:一句话 vision,能让 BIO / MPS 的评审也觉得"这说的是我的数据"。

> ⬜ **需你定**:接受 C 吗?还是你心里的 "ambitious" 指别的(例如换 solicitation、或以 agent 研究本身为主角)?

## F1 Grand Challenge —— 解锁之后,能回答什么以前回答不了的科学问题?

NSF 评审看的是**科学发现**,不是数据工程。每个域要有**一个具体的、今天做不到的问题**:

| 域 | 今天做不到的事 | 为什么被锁 |
|---|---|---|
| 无线网络(我们) | 跨运营商、跨年份的**跨层故障归因**大规模研究 | 科学量(RSRP、调度、层间事件)只在 XCAP 类工具解码后存在;配置决定真值(T5) |
| 流式细胞术 | 跨实验室**合并**历史 FCS 数据做免疫表型的 meta-analysis | 门控在 FlowJo 里手画,亚群计数依赖不可见的门控策略 |
| 质谱 / 蛋白组学 | 回溯重分析存量 .raw 数据,使**不同软件版本的结果可比** | 定量依赖厂商算法与默认参数 |
| 材料表征(XPS/XRD) | 用历史表征数据训练材料性质模型 | 峰拟合参数决定结论,只存在于 GUI 会话里 |

**跨域的统一科学主张** ⭐:
> **大量存量科学数据的"结论"其实是 f(数据, 工具, 配置),而配置部分从未被记录。**
> 这不仅锁住了数据,还意味着**已发表的跨研究比较可能本来就不可比**。

这是一个**可证伪的、关于科学数据本身的主张** —— 比"数据难用"锋利得多。

**过关标准**:≥3 个域,每个域一句"今天做不到的科学问题",并且有该域 PI 认可。

> ⬜ **需你定**:第二、第三个域选哪几个?(v1 推荐流式细胞术为首选)

## F2 瓶颈命名与规模 —— 这到底有多大?

v1 已有命名:**instrument-locked datasets**。野心版还缺**规模数字**,没有它撑不起 Flagship 的"significantly large research community"。

需要的数字(🔴 **全部待查,不得拍脑袋**):

| 要证明的 | 可能的数据来源 |
|---|---|
| 有多少科学数据是通过厂商分析软件产生的 | 大学核心设施目录;NSF MRI(Major Research Instrumentation)历年资助的仪器数量 |
| 有多少核心设施 / 仪器 | ABRF(Association of Biomolecular Resource Facilities)、各校 core facility 列表 |
| 公共仓库里有多少这类原始文件 | PRIDE / MassIVE(质谱)、FlowRepository(流式)、Materials Data Facility |
| 跨研究不可比的实证 | 流式/质谱领域的可复现性研究文献 |

⭐ **一个值得做的小型 census**(1 周内可完成):抽样 50 篇近年 NSF 资助的实验论文,
统计"关键数值由厂商 GUI 软件产生、且未记录处理配置"的比例。
**这个数字本身就可以是提案的开篇证据**,和我们的 13 行"软件自述不可信表"一起用。

**过关标准**:至少一个量化规模数字 + 一个跨域的"配置未记录"比例。

## F3 Why Now

| 变化 | 为什么现在才可能 / 才必要 |
|---|---|
| **Computer-use agent 跨过可用门槛**(2025–26) | 以前解锁 GUI-only 数据只能靠人工或厂商 SDK;现在可以自动化 —— 但**正确性不可见**,这正是研究问题 |
| **NSF / 国家层面推 AI-ready data** | 26-512 本身就是信号;存量数据是最大的未开发资源 |
| **Agent 提取的数据即将大量涌入科学管线** | 🔴 **如果没人先建验证层,未来几年会产出大量带静默语义错误的 AI 训练数据** —— 这是紧迫性论证 |

最后一行是野心版的**紧迫性钩子**:不是"这件事很有用",而是"**不做会出事**"。

## F4 Intellectual Merit —— 为什么这是研究,不是 RPA 工程?

🔴 **这是 Flagship 能否成立的核心。** 每个研究问题都必须是**开放的**,有失败可能。

| # | 研究问题 | 为什么难 / 为什么开放 | 我们的基础 |
|---|---|---|---|
| **Q1 语义推断** | 能否从**黑盒**分析软件的输入-输出行为中,自动推断出它在各配置下计算的是什么? | 类似 specification mining,但对象是零文档 GUI 程序,配置空间组合爆炸 | T5 配置决定真值;5 个沉默默认值 |
| **Q2 无真值条件下的可信提取** | 当被提取的量本身没有 ground truth 时,怎么证明 agent 的提取是对的? | 工具会对自己的行为"撒谎"(13 行表);成败信号藏在第四处(mtime) | 双通路独立验证:99.4% / 50/50;"先证明两条通路独立"的方法论 |
| **Q3 跨仪器泛化** | 一套 agent + 验证架构,能否以低边际成本移植到新仪器域? | 每个域的界面、格式、语义都不同;需要量化"移植成本" | 🔴 待建 —— 这是新工作 |
| **Q4 回溯审计** | 给定一个已发表的数据集和它可能用过的工具版本,能否判断它带了哪些语义偏差? | 需要把语义目录反向用于存量数据 | 语义溯源目录的设计 |

**核心主张一句话**:
> **把"科学软件实际计算了什么"变成一个可测量、可验证、可累积的对象。**

**过关标准**:每个 Q 都有 (1) 一个会让它失败的结果,(2) 一个评估方法。

## F5 社区结构 —— 怎么把"单域团队"变成"大社区"?

v1 的最大风险是社区广度。野心版的解法不是**多拉几个 PI**,而是**换一个社区单元**:

| 方案 | 社区单元 | 规模 | 可行性(40 天) |
|---|---|---|---|
| v1 | 每域 1 个伙伴实验室 | 小 | 中 |
| **野心版** ⭐ | **核心设施网络**(每个设施服务几十到上百个实验室) | 大 | 需要 1–2 个设施主任点头 |
| 远景 | 专业协会 / 设施联盟(如 ABRF;流式领域的 ISAC) | 很大 | 40 天内只能拿到"支持信",拿不到承诺 |

⭐ **为什么核心设施是对的单元**:
- 仪器集中在那里,厂商软件 license 也在那里
- 他们**天然承受**"用户问我这个数是怎么算的"的痛
- 一个设施 = 一封 Letter of Collaboration = 几十个下游实验室 —— **杠杆最大**

**推荐的社区组成**(Flagship 版):
1. 我们:无线网络(CISE),已有全部实测
2. 本校 1–2 个核心设施(流式 / 质谱),**UMN 内部最好谈**
3. 1 个外校或国家设施(材料表征或电镜)
4. 1 个数据仓库方(接收解锁后的数据)—— 解决 §4 可用性
5. 一个协会的支持信 —— 撑 outreach

**过关标准(10-14 决策门,修订 v1 §5.3)**:

| 条件 | 投档 |
|---|---|
| ≥3 个非 CISE 域 + ≥1 个设施 + 1 个仓库方,都有明确承诺 | 🟢 **Flagship** |
| 2 个非 CISE 域有明确承诺 | 🟡 **Impact**(野心写在 vision 里) |
| ≤1 | 🔴 按 v1:Planning 或不投 |

> ⬜ **需你定**:UMN 有哪些 core facility 你能直接接触?有没有已经认识的设施主任或 co-PI 人选?

## F6 推力与交付物

在 v1 的 R1–R4 基础上,按 F4 重组,并加一个平台推力:

| 推力 | 对应 Q | 交付物 |
|---|---|---|
| **T1 Instrument Semantics** | Q1 | 语义推断方法 + **语义溯源目录**(机器可读) |
| **T2 Verifiable Extraction** | Q2 | agent 提取管线 + 独立验证通路框架 |
| **T3 Cross-Instrument Generalization** | Q3 | ≥4 个仪器域的移植,附移植成本曲线 |
| **T4 Readiness & Retroactive Audit** | Q4 | 数据集就绪度评估 + 存量数据审计工具 |
| **T5 Community Commons**(Flagship 才有) | — | 开放目录 + 贡献流程 + 设施部署 + 年度 workshop |

⭐ **T5 是 Flagship Justification 的主体**:它把研究产出变成一个持续运营的社区资源,
正好对应 solicitation 的 *"support a significantly large research community"*。

## F7 证据映射 —— 我们手里已经有什么

| Q / 推力 | 已有证据 | 缺口 |
|---|---|---|
| Q1 / T1 | T5 配置决定真值(−20.0 vs −12.9);5 个沉默默认值;308 表 `Layer2` 零表 | 只有一个工具 |
| Q2 / T2 | 13 行自述不可信表;99.4% L1 对账;50/50 L2 双通路 | agent 本身还没建 |
| Q3 / T3 | 容器解析跨四条产线成立 | 🔴 **没有任何非无线网络域的初步结果** |
| Q4 / T4 | detector battery + 13 项测试 + 五个决策门 | 未在存量数据上跑过 |
| 社区 | — | 🔴 全部待建 |

🔴 **Q3 的缺口最危险**:评审会问"你凭什么说能泛化"。
**建议在 10-14 前**,用 1 个伙伴域做一个极小的 pilot(比如一份 FCS 文件,两种门控策略,展示计数差异)。
一张图就够,它把 Q3 从"主张"变成"有初步证据"。

## F8 Panel Red Team —— 评审会怎么杀这个提案

| 攻击 | 我们的回应 | 状态 |
|---|---|---|
| **"这就是 RPA / 工程"** | F4:四个开放研究问题,各有失败条件;Q2 在无真值条件下验证是公认难题 | 🟡 措辞要锋利 |
| **"ProteoWizard 等已经解决了"** | 它们解决的是**格式**;我们解决的是**语义与配置** —— 有 T5 类证据区分 | 🟢 |
| **"厂商 license / ToS 不允许"** | 我们只操作合法持有的 license;license 稀缺反而证明需要 agent;交付物不含厂商原始文件 | 🟡 需要学校法务确认一句话 |
| **"agent 不可靠"** | 正是我们的研究问题 —— 我们不假设 agent 可靠,我们建验证层 | 🟢 这是最强回应 |
| **"团队是网络背景,凭什么做生物数据"** | 核心设施伙伴提供域专长;我们提供的是**跨域不变的**方法 | 🔴 取决于 F5 |
| **"Flagship 规模没必要"** | T5 社区资源 + ≥4 域 + 设施部署,Impact 预算做不完 | 🔴 取决于 F5 |
| **"de novo 数据采集,out of scope"** | 我们不采集;全部是存量数据 | 🟢 |

**过关标准**:所有 🔴 在 10-14 前变成 🟡 或 🟢;否则降档。

## F9 收敛 —— 标题、一页 vision、投档

**标题候选**(Flagship 版):
- `AIDatasets:Flagship: Instrument Semantics — Making Instrument-Locked Scientific Data Auditable and AI-Ready`
- `AIDatasets:Flagship: Unlocking and Verifying Instrument-Locked Scientific Data at Scale`

**一页 vision 骨架**(给伙伴的 concept note 直接用这个):
1. **钩子**:科学结论 = f(数据, 工具, 配置),配置从未被记录 —— 附一个跨域例子(T5 + 门控)
2. **后果**:存量数据被锁;已发表的比较可能不可比;agent 提取即将让问题放大
3. **Vision**:建立 *instrument semantics* 层
4. **四个研究问题**(Q1–Q4)
5. **社区**:核心设施网络 + 仓库 + 协会
6. **交付物**:语义目录 · 验证框架 · 解锁数据集 · 审计工具
7. **我们为什么能做**:13 行表、T5、双通路验证 —— 已实测

**Problem Card**(10-14 前填完):

| | |
|---|---|
| Problem | |
| Why important(带数字,来自 F2) | |
| Why hard | Q2:无真值条件下的验证 |
| Why unsolved | 格式转换工具不处理语义;agent 不处理验证 |
| Why now | F3 |
| Key insight | 工具的行为是可测量对象;独立通路可以替代缺失的 ground truth |
| Community | F5 |
| Biggest risk | 社区广度 / Q3 无初步证据 |
| 投档 | 10-14 决定 |
