## 0. 一条贯穿的设计原则

> **coding agent 白拿的东西,这里都要自己造。**
> 而其中最反直觉的一条是:**软件说的话不能信。**

⇒ **本 agent 的核心设计目标之一,是"不轻信宿主软件的自述"** ——
这正是 [[baseline_status/ASTRA-EVAL-SPEC]] 的 **P5 探针**要测的能力。
**我们指控现有模型缺它,那我们的 agent 就必须有。** 见 §3 的 **X1**。

|---|---|

### M3 — 事务化动作

| | C3.1 事务化 |
|---|---|
| 循环 | `声明 intent → 执行 → 用 state diff 核验后置条件 → 不符则诊断并重试/回退` |
| 🔴 约束 | **`ActionResult` 必须带 `state_diff`,不得只回 `ok`** —— 任何 RPC/MCP 层都看不见 GUI 状态是否真变了 |

| | C3.2 静默失败检测 |
|---|---|
| 指标 | 静默失败检出率;无 M3 时的错误传播长度 |
| ⬜ 依赖 | **A9 尚未提供基线静默失败率** —— M3 唯一的实证数字,7 分钟可得 |

| | **C3.3 ⭐ 全局副作用扫描** |
|---|---|
| 为什么 | 🔴 **Filtering 是全局的**(跨 Graph/Map/Table/CDF/PDF)⇒ 一个窗口的操作改变所有窗口的读数 |
| 做什么 | `apply_filter` 的 state diff **必须扫全工作区**,不能只看当前窗口 |
| 其它全局项 | Area/Route Binning 会**产生持久化派生状态**(挂进参数树,甚至生成新 Model)→ **状态空间可递归增长** |

| | C3.4 结构化动作优先 |
|---|---|
| 做什么 | filter = `(param, op ∈ {=,<>,>,>=,<,<=}, value, linker ∈ {AND,OR,None})` 有序列表 —— **声明式,可生成可 diff,不该用拖拽像素表达** |
| 推广 | 先找软件内部的结构化意图层,找不到才退化为坐标点击 |

## 2.7 ⭐⭐⭐ 递归自我改进(RSI)—— 六个机制闭合成的环

> **这不是第七个机制,是 M1 / M5 / M6 闭合之后自然形成的循环。**
> 单独列出来,是因为它决定了**评测协议**(见 §2.7.5),而那件事按现在的设计根本测不出来。

### 2.7.1 为什么 RSI 在这个设定下**不是野心,是唯一出路**

三条约束把其它所有变强的途径都堵死了:

| 约束 | 堵死了什么 |
|---|---|
| **零文档**(且文档不可信) | 不能靠预训练获得领域知识 |
| **零演示**(无 GUI 轨迹、无专家示范) | 不能模仿学习 |
| **实例数受限**(capacity 待封口,规划按 1) + `λ·N_live_interactions` | 不能穷举探索 |

⇒ **唯一能变强的途径,是把已经花掉的交互复利化。**

⭐ **这是论文里最强的论证形式**:RSI 不是我们想做的东西,是**被约束逼出来的唯一解**。
而这三条约束**恰恰是专业商业软件的常态** —— 所以这个设计对整类软件成立,不只对 XCAP。

### 2.7.2 三个闭环

```
① 技能环
   探索 ──→ verifier 判定成功 ──→ 抽取技能 ──→ ┬→ 编译为 .fav(宿主原生)
                                              └→ 注册为新 typed action
        ↑                                              │
        └────── 动作面扩大,更难的任务变得可达 ←─────────┘

② 认知环
   语义标定(C1.3) ──→ 软件手册 ──→ 更好的动作选择 ──→ 更多语义被发现
        ↑                                                    │
        └────────────────────────────────────────────────────┘

③ ⭐ verifier 环  ——  最关键的一个
   verifier 变强 ──→ 能判定更难的任务 ──→ 更多轨迹可被认定为"成功"
        ↑                                          │
        └── 技能库更好,验证手段更多 ←──────────────┘
```

🔴 **③ 是瓶颈环。** 零演示设定下 **verifier 是唯一的教师** ——
verifier 判不了的任务,轨迹再多也学不到东西。
⇒ **C7.4 verifier 自举的优先级高于 C6.x 技能抽取**,顺序不能反。

### 2.7.3 闭环的四个必要条件(缺一即开环)

| 条件 | 能力 | 缺了会怎样 |
|---|---|---|
| 知道哪条轨迹值得学 | **C5.2** 自建 verifier | 学到噪声 |
| 跨 session 持久化 | **C6.2** 双投影 | 每次从零开始,环不闭合 |
| 库大了找得到 | **C6.3** 索引与检索 | 技能库变成垃圾场 |
| 🆕 **预算有限,选对下一个任务** | **C7.1 课程选择** | 交互预算耗在学不到东西的任务上 |

### 2.7.4 🔴 四种失败模式(必须写,否则 RSI 是空话)

| # | 失败模式 | 后果 | 对策 |
|---|---|---|---|
| **F1** ⭐ | **技能污染** —— 一条错技能入库,后续全部被污染 | 与 GT 的 **implicit B 同型**:错误不可见且随能力增长而放大 | **C7.2**:provenance + 留出验证 + **可回滚** |
| **F2** | **verifier 漂移** —— verifier 本身错了,并自我强化 | 环 ③ 变成正反馈的错误放大器 | 独立通路交叉验证(**C2.4** 的多通路正好是这个用途) |
| **F3** | **局部最优** —— 早期形成的坏习惯被锁死 | 曲线早早变平 | C7.1 课程里保留探索配额 |
| **F4** | **预算耗尽** | 环还没转起来就停了 | C7.3 监控边际成本,不见复利就止损 |

⭐ **一个值得写进论文的对称**:

> **M4 说:环境没有 `git checkout`,所以探索昂贵。**
> **RSI 说:agent 自己的知识库必须有 `git`,否则一条错技能就毁掉整个学习过程。**

**外部世界不可回滚,内部记忆必须可回滚。** 这两件事一起构成本 agent 的记忆架构。

### 2.7.5 🔴🔴 评测协议的含义 —— **现在的设计测不出 RSI**

| 现状 | 问题 |
|---|---|
| 所有评测都是**每任务独立 × 3 seed** | **i.i.d. 协议下,复利效应在定义上不可见** |
| 任务无序呈现 | 学习曲线无意义 |

⇒ **必须新增一种评测模式:**

```
career mode(纵向):任务按固定顺序呈现,记忆跨任务持续
  ├─ 主曲线:第 k 个任务的边际成本(live actions)vs k
  ├─ 对照:同一 agent 关闭持久化(记忆每任务清空)
  └─ 迁移:在从未见过的任务族上测增益  ← 真正的检验
```

🔴 **三条协议纪律**:
1. **学过的任务不能再用于测量**(污染),需预留纯测试集
2. **顺序是实验变量**,至少跑两种顺序看结果稳不稳
3. **对照组必须是同一个模型关掉记忆**,不是另一个 baseline

⚠️ 这对 [[BENCHMARK-DESIGN]] 与 [[baseline_status/ASTRA-EVAL-SPEC]] 都有改动含义 —— 待回写。

### 2.7.6 度量

| 指标 | 说明 |
|---|---|
| ⭐ **边际成本曲线** | 第 k 个任务所需 live actions vs k。**这是 RSI 的主图** |
| 动作面规模 | 自撰动作数 vs k |
| **自撰动作承担率** | 由自撰动作(而非原语)完成的动作占比 |
| 技能复用率 / 命中率 | |
| ⭐ **留出迁移增益** | 未见任务族上 B6 − B5 |
| 🔴 **污染率** | 入库后被证伪的技能占比(F1 的直接度量) |

⭐ **负结果也是结果**:若曲线平坦,就是对"skill 复用能否降低成本"这一问题的**否定证据**,
与已有文献中 skill 复用的否定结论形成对话。**这条路两头都有话说。**

### 2.7.7 ⚠️ 术语

论文正文建议用 **compounding skill acquisition** / **self-extending action space** 一类说法,
把 "recursive self-improvement" 留作内部概念 —— 该词在审稿语境里容易被读成过度声称,
而我们的主张其实**很具体也很可测**:动作面会长大,边际成本会下降,且两者都有曲线。

### X4 🔴 跨层时间对齐

| 事实 | 含义 |
|---|---|

### X7 🆕🔴 更正传播(Correction Propagation)

**这是 C5.3 抓不到的第四类错误。** C5.3 的三次教训(判据坏 / 测具坏 / 报告代码坏)**共同点是某个环节真的坏了**;
而 09-09 这一批**没有任何环节坏掉** —— 数据对、测量对,**坏的是记录与实际之间的同步**。

> 🔴 **前三类加一个阳性对照就能抓到;这一类抓不到** —— 每处单独看都是对的,
> **矛盾只在并排看两份文档时才出现。**

**人类基线(现成且刺眼)**:`A3`(09-02 **05:43**)已写「试着同时开第二个实例看是否被拒」,
而 `A7`(**同一天 07:40**)测的却是第 3 个、把 `Num of Analyzer = 1` 抄进表却在结论栏写 ✅ ——
**该结论存活 7 天,扩散到 4 份规格的 5 处,全部原样引用,无一处带边界。**

| | |
|---|---|
| 要求的行为 | ① 每条断言带 **来源 + 日期 + 观测条件**<br>② 断言被更新时,**主动去找所有引用它的地方**<br>③ 引用他处断言时**检查其是否仍然成立**,而不是原样复制 |

```
substrate(W02:序列化 / typed action / state diff / 检查点控制器)
```

🔴 **三条关键路径**:
